## 1. 范围

一局 9 人：**真人 N 人（1–9，可配置）+ AI 补位至 9 人**，纯文本网页界面。
本版**不做**：账号 / 匹配 / 持久化 / 美术 / 扩角色 / LLM 玩家 / 联机。
（联机在 v3 单独做，见 §11 预留口。）

本版在 v1 基础上**新增**：警长竞选（含 PK、退水）、警徽流（含生前预设）、遗言阶段、
白天定发言顺序。**v1 的「不设警长 / 不设遗言」两条限制作废**，其余沿用（见 §12.1-F）。

## 2. 板子配置与节奏推演

| 角色 | 数量 | 阵营 | 边 |
|---|---|---|---|
| 狼人 | 3 | 狼人 | — |
| 预言家 | 1 | 好人 | 神 |
| 女巫 | 1 | 好人 | 神 |
| 猎人 | 1 | 好人 | 神 |
| 村民 | 3 | 好人 | 民 |

**胜负口径先行**（判定细则见 §6）：

- 狼胜：**神职全灭（神边屠尽）或 村民全灭（民边屠尽）**，任一成立即狼胜
- 好人胜：**狼人全灭**

**节奏推演**（先口径，后结果；S1 不做平衡调优，只验证可达性）：

- 狼方最快路径（理想无干扰）：连杀同一边 3 人 → 第 3 夜结束即达成屠边 = **3 夜 0 日**
- 好人方最快路径：首夜女巫毒 1 狼（同夜狼刀另杀 1 好人，双死，余 2 狼）→ 日投 1 狼（余 1 狼）→ 次夜女巫毒最后 1 狼（狼刀再杀 1 好人）→ **2 夜 1 日**
- 结论：女巫毒药让好人具备「抢节奏」能力，屠边把胜负从"人数比"改成"边全灭"。
  **本版不做数值平衡**，只保证规则自洽、每局必然终止。

**警长对节奏的影响（1.5 票改变放逐阈值）**：

- 放逐口径从「数人头」变成「数票权」。9 人存活、3 人投 A、3 人投 B、2 人弃票、警长尚未投票时，
  3 : 3 是平票（平安日）；警长投 A → **4.5 : 3**，A 直接放逐。
- 也就是说：**警长一票足以单独打破平票**，好人方靠警长把"平安日"收敛成"放逐"，
  狼方则要先处理警长或抢到警徽。本版节奏比 v1 更集中，平安日更少。
- 首夜死亡者有遗言、首个白天又有竞选，**第 1 个白天的公开信息量显著高于 v1**。

## 3. 角色技能

| 角色 | 夜间行动 | 说明 |
|---|---|---|
| 狼人 | 共同刀 1 名存活者 | 3 狼互知身份，一队一个声音；**禁刀狼队友** |
| 预言家 | 验 1 名存活者 | 结果「好人 / 狼人」二值；**禁验自己**；不细分神民 |
| 女巫 | **解药救被刀者 / 毒药毒 1 人** | 解药 1 瓶 + 毒药 1 瓶，**同一夜只能使用其中一瓶**；能得知本夜刀口；解药可救刀口，毒药可毒任意存活者 |
| 猎人 | 无夜间行动 | **死亡时可开枪**带走 1 名存活者（详见 §3.2） |
| 村民 | 无 | — |

### 3.1 女巫细则（标准口径）

1. 解药与毒药**各 1 瓶，用完即无**。
2. **同一夜只能使用一瓶**（不能既救又毒）。
3. **解药可救任何人，包括自己；任意夜都可自救**（D66 已定；原「仅首夜可自救」的疑问作废）。
4. 毒药**不能毒自己**。
5. 女巫**不知道**被刀者身份；**解药生效则该玩家不死亡，且不产生死亡事件**
   —— 因此也不产生遗言、不触发判胜。
6. 女巫已死则夜间跳过女巫行动。
7. 女巫用药后，仍会在次日天亮时被告知结果（药是否生效由日志体现）。
8. **一夜最多 2 名死者**：女巫用毒时**狼刀照常生效**（「同夜只用一瓶」限制的是女巫自己，不阻止狼刀）；只有**解药生效才是 0 死**。若毒药目标恰好就是刀口，只算 1 死（死因按 §12.1-P 记 `poison`）。

### 3.2 猎人细则（标准口径）

1. 猎人**被狼刀死**或**被投票放逐** → **可以开枪**带走 1 名存活者；
2. 猎人**被女巫毒死** → **不能开枪**；
3. 开枪是**独立一步**（`hunter_shoot` 阶段）：命中 → 目标立即死亡 → **立即判胜负**
   （枪杀可达成屠边）；
4. 猎人可选择**不开枪**（弃枪，D66 已定合法）；
5. 猎人开枪与否由该玩家（真人）或 AI 策略决定；
6. **遗言与开枪是两件事**：猎人是否有遗言只看**死亡时点**（§5.3），不看死因；
   **开枪永远在遗言与警徽移交之后**（理由见 §5.7-3）。
7. 猎人若同时是在位警长：**遗言（若有）→ 警徽移交 → 开枪**。顺序理由：
   警徽移交写在遗言之后、开枪之前，才能保证「枪杀立即终局」不会吞掉警徽归属；
   若先开枪且枪杀直接判胜，警徽与遗言都会被跳过，盘面与胜负解释不一致。

## 4. 明暗牌模式

局前选择，影响**死亡时是否公开身份**：

| 模式 | 死亡时 | 终局时 |
|---|---|---|
| 明牌（`open`） | 立即公开死者身份（翻牌） | 公布全员身份 |
| 暗牌（`dark`） | **不公开身份**，只公布「N 号出局」 | **公布全员身份**（已定） |

- 暗牌局中，**死亡信息本身公开**（谁出局人人可见），只是**身份不公开**。
- 屠边判定的计算在引擎内部进行，**不向玩家泄漏**「哪条边被屠了几个人」。
- AI 在暗牌局中只能用公开信息决策（不知道死者身份）。
- **遗言与警徽移交不改变翻牌口径**：暗牌局里遗言可以自称任何身份（发言可以撒谎），
  死亡时仍不翻牌；警徽移交给谁是公开事实，但**不移交**也不代表死者身份如何。

```ts
  | { type: 'sheriffSignup'; join: boolean; actor?: Seat }
  | { type: 'withdrawElection'; actor?: Seat }        // 仅 sheriff_speak、本人发言/跳过后、每人一次
  | { type: 'speak'; text: string; claim?: Claim; actor?: Seat }
  | { type: 'skip'; actor?: Seat }
  | { type: 'castVote'; target: Seat; actor?: Seat }
  | { type: 'abstain'; actor?: Seat }
  | { type: 'setSpeechOrder'; start: Seat; direction: 'asc' | 'desc'; actor?: Seat }
  | { type: 'lastWords'; text: string; badgeTo?: Seat | null; actor?: Seat }
  | { type: 'skipLastWords'; badgeTo?: Seat | null; actor?: Seat }
  | { type: 'hunterShoot'; target: Seat }
  | { type: 'hunterPass' }
  | { type: 'setBadgePreset'; target: Seat | null; actor?: Seat }  // 相位无关，见 §5.4
  | { type: 'confirm' };
```

> **`actor` 必带**（真人 > 1 时）：联机/多人 hot-seat 下不能靠「当前行动者」推断，
> 服务端必须校验 `actor`。单人局可省略（沿用 S0 兼容口径）。
> `sheriff_speak` 内的 `confirm` 语义 = **「不退水，进入下一位候选人」**；
> `withdrawElection` 只在该阶段、且本人已发言/跳过后合法，每人一次。

补充口径（均来自已定规则，无新增）：

- **竞选只发生一次**：`round=1` 的白天。警徽流失后不再竞选（§5.4）。
- **交接页与自动推进**：`dawn` / `day_exile` / `badge_transfer` 无人工选择，驱动层自动推进，
  但在转移表中保留为显式阶段，测试可直接对转移函数打点（沿用 S0 做法）。
- **定序**：`day_order` 只在进入白天且**警长存活**时出现；无警长直接 `day_speak`
  （座位升序，§12.1-F）。

### 5.3 死亡结算链：遗言、警徽移交、开枪的先后

**判遗言权只看「死亡时点 + 死亡场合」，不看死因**（Lisa 2026-10-18 追加）。
同一夜可以有 **2 名死者**（狼刀 + 毒药），两名死者**分别**适用下表：

| 死亡时点 / 方式 | 遗言 | 依据 |
|---|---|---|
| **首夜**（round=1 的夜晚）死亡，**任何死因**（被刀 / 被毒 / 被枪打中） | **有** | 时点判定 |
| 白天被放逐 | **有** | 放逐恒有遗言 |
| 第 2 夜起被狼刀 | 无 | 不在上述两种场合 |
| 第 2 夜起被毒 | 无 | 同上 |
| 白天（非放逐）被枪打中 | 无 | 同上 |

> **首夜枪伤致死也按首夜算**：首夜猎人被刀 → 先遗言 → 开枪 → 被枪打中者
> **同样有遗言**（仍属首夜时点），之后才进入竞选。
> **首夜双死**（狼刀 + 毒药，目标不同）：两名死者都有遗言，按「狼刀 → 毒药」顺序处理。
> **同一目标同时被刀又被毒**：只算 **1 死**，`cause` 记 `poison` —— 因此猎人**不能开枪**（§3.2-2 / §12.1-P ③）。

**一个结算点 = 结算 + 后续链**（唯一口径，`resumeAfter` 在进入链条时记录）：

```text
# 结算点有三种：夜间（0–2 人：狼刀 + 毒药）、放逐（1 人）、枪杀（1 人）
settlePoint(deaths, window):            # window: 'first-night' | 'night' | 'day'
  1. for d in deaths: player_died(d)     # 明牌局带 revealedRole；暗牌局不带
  2. checkVictory()                      # 全部死亡记录完再判一次（§6）
  3. for d in deaths: afterDeath(d, window)

afterDeath(d, window):
  3.1 若 d 有遗言权（window=='first-night' 或 d.cause=='exile'）
        → last_words（动作内可宣布/调整警徽流）
  3.2 若 d 是在位警长
        → badge_transfer（目标：遗言有效指定 > 生前预设 > 未指定→作废）
  3.3 若 d 是猎人 且 d.cause ∈ {night-kill, exile}
        → hunter_shoot；命中 → 立即结算被枪者（记录死亡 → 判胜 → 其后续链），完成后回队列
  3.4 队列下一位死者；队列空 → 最外层结算点才执行 resumeAfter
```

五条关键性质：

1. **遗言与警徽移交解耦**：移交不依赖遗言。第 2 夜警长被刀（不产生遗言）时，
   玩家不发言，但**仍单独执行一次 `badge_transfer`**，按生前预设生效。
2. **先遗言、后警徽、再开枪**（死者同时是警长和猎人时的唯一顺序）。
   理由见 §5.7-3。
3. **同一次死亡最多 1 次移交**；但枪杀造成的"第二次死亡"是**另一次**结算，
   若被枪者正好是新接任的警长，会再触发一次 `badge_transfer`（边界见 §5.8）。
4. **判胜优先于一切后续动作**：第 2 步一旦成立，遗言、移交、开枪全部跳过（§6）。
5. **同一夜可双死**：两名死者的后续链按「狼刀 → 毒药」顺序逐个执行（某位死者的枪杀新死亡**先处理完**，再轮到队列下一位）；判胜用**全部死亡记录完后的一次检查**（避免"先死先赢"，§12.1-P）。

### 5.4 警徽流（生前预设 + 死亡移交）

**为什么要有预设**：警长最常见的死法是夜里被刀，而夜死（第 2 夜起）没有遗言。
若移交只能靠遗言，警徽流在多数局里等于不存在。因此**移交是独立动作，预设让它始终可执行**。

| 项 | 口径 |
|---|---|
| 预设控件 | 警长**活着时随时可改**：`setBadgePreset({target})`。目标必须**存活且 ≠ 自己**；`null` = 未指定 |
| 相位 | **相位无关**（不限 `phase`），校验只有两条：行动者是在位警长、且存活；不改状态机、**不产生事件**（只更新隐藏字段） |
| 可见性 | **仅警长本人可见**（`viewFor(sheriff).myBadgePreset`）。其他玩家、AI 都看不到；终局也不回溯公布（避免"警长当时就信任谁"的假信息） |
| 预设目标先死 | 视为**未指定**（§12.1-M：警徽作废） |
| 死亡解析 | 遗言里**显式给出的有效目标** > **生前预设**（须存活）> **未指定 → 流失** |
| 遗言里给 `null` | 明确作废，**不**回落到预设 |
| 遗言里给无效目标 | 视为未指定，**回落到预设**；预设也无效 → 流失（§12.1-M） |
| 接任者 | `sheriff.seat = to`，1.5 票权生效时点：**死亡移交的接任者从下一次投票起**、**新当选者从当天的放逐投票起**；接任者获得自己的预设控件（初始未指定；AI 按 §7.3 自动求值）。**接任者可在移交公告页当场设置**，不必等到下一个白天 |
| 流失 | `badgeLost = true`，本局不再有警长、不再竞选，`day_order` 不再出现。**0 人上警 / 全员上警 / 全部退水 / PK 再平票 也置 true**（语义 = 本局不会再产生警长） |
| 移交次数 | 不设上限：接任者死亡且条件满足时可再传 |

```ts
interface SheriffState {
  seat: Seat | null;            // 当前警长；null = 无警长
  electedRound: number | null;  // 竞选轮次（本版恒 1）
  badgeLost: boolean;           // 已流失：不可回退、不再竞选
  badgePreset: Seat | null;     // 生前预设（隐藏字段，仅警长本人可见）
}
```

### 5.5 计票口径（1.5 票 —— 全文唯一出处）

**票权以「半票」为整数单位**，避免 x.5 的浮点比较问题：

```ts
weightHalf(seat) = (seat === sheriff.seat ? 3 : 2);   // 警长 1.5 票 = 3 半票
tallyHalf[x]     = Σ weightHalf(voter)               // 只统计投给 x 的票，弃票不计
display(x)       = tallyHalf[x] / 2                  // 展示可以为 x.5
```

- **比较一律用 `tallyHalf` 整数**；`display` 只用于 UI 与日志。
- **最高票**：`max = max(tallyHalf)`；取到 `max` 的座位集合 S。
  - `|S| = 1` → 唯一最高 → 当选 / 放逐
  - `|S| ≥ 2` → 并列最高 → 警长竞选进 PK；放逐则平安日（§12.1-F）
  - `max = 0`（全员弃票）→ 无人当选 / 平安日
- **不设「过半数」门槛**：本版三处投票（警长首投、PK 再投、每日放逐）**都取相对多数**。
  若将来引入过半门槛，统一口径为 `2 × tallyHalf > totalHalf`
  （`totalHalf` = 未弃票者的票权之和），同样用整数比较。
- **1.5 只在放逐投票生效**：首个白天的竞选期间场上没有警长（全员 1 票）；
  本版不重新竞选，故竞选相关投票恒为 1 票/人。
- **推论（可作测试自检）**：场上只有 1 名警长，含警长票的一方半票数为奇数、
  不含者为偶数 → **两个 x.5 不会并列**；平票只能出现在「警长未投的候选人」之间。

防歧义用例：

| 场景（9 人存活） | 半票计 | 展示 | 结论 |
|---|---|---|---|
| 警长 + 2 人投 A；3 人投 B；3 人弃票 | A 7 / B 6 | 3.5 : 3 | A 唯一最高（**不是平票**） |
| 警长 + 1 人投 A；2 人投 B；5 人弃票 | A 5 / B 4 | 2.5 : 2 | A 唯一最高 |
| 警长投 A；3 人投 B；3 人投 C；2 人弃票 | A 3 / B 6 / C 6 | 1.5 : 3 : 3 | B、C 并列最高 → PK / 平安日 |
| 全员弃票 | 0 | 0 | 无人当选 / 平安日 |
| 警长投 A；3 人投 B；5 人弃票 | A 3 / B 6 | 1.5 : 3 | B 唯一最高 → 放逐 |

### 5.6 首个白天的固定顺序（含理由）

```text
天亮，公布死讯（dawn confirm）
  → 首夜死者遗言（任何死因；若是猎人，先遗言）
  → 猎人开枪（若有）→ 被枪者（同属首夜）遗言
  → 上警报名（sheriff_signup）
  → 上警者依次发言（sheriff_speak；每人发言/跳过后可退水一次）
  → 警下投票（sheriff_vote；候选人 = 未退水者，投票人 = 警下）
  → 平票 → PK 发言（sheriff_pk_speak）→ 警下再投（sheriff_pk_vote）
  → 当选（sheriff_elected）/ 无警长
  → 警长定发言顺序（day_order；无警长则跳过）
  → 白天发言（day_speak，按警长定的顺序；无警长则座位升序）
```

**为什么死讯与遗言必须在竞选之前**：玩家要先知道"谁死了、死者说了什么"，才有信息
决定自己上不上警、投谁。若竞选先跑，首夜死亡信息与遗言就浪费了——这是本版把
`last_words` 放在 `sheriff_signup` 之前的唯一理由。

> 注：首夜没有警长，所以「警徽移交」不会出现在首日的上半段；`badge_transfer` 最早出现在第 1 个白天的竞选之后（警长当选后被放逐/被枪杀时）。

### 5.7 关键时序约束

1. **夜间顺序固定**：狼刀 → 女巫 → 预言家验 → 天亮结算。女巫先于预言家，因为女巫需要知道刀口。
2. **夜死结算在 `dawn` 入口统一处理**：解药生效则不产生 `player_died`；否则产生 **1–2 名**死者（狼刀 + 毒药）。
3. **遗言 → 警徽移交 → 开枪**（死者同时是警长和猎人时的唯一顺序）。理由：
   ① 警徽移交放在开枪之前，枪杀立即终局时才不会吞掉警徽归属；
   ② 遗言放在移交之前，警长才能"临时改主意"（遗言里显式指定覆盖预设）；
   ③ 遗言放在开枪之前，死者的最后表态（"我为什么打谁"）先于结果落地。
4. **警徽移交独立于遗言**：不产生遗言的场合（第 2 夜起被刀/被毒、白天被枪）照做，
   玩家不发言，系统按生前预设执行并**公开公布新警长**（§5.4）。
5. **判胜即时**：每次死亡结算（夜死 / 放逐 / 枪杀）后立即判定；成立即 `game_over`，
   **跳过遗言、警徽移交与开枪**。遗言阶段本身不判胜（无死亡、移交不改变存活）。
6. **每夜 0–2 名死者**：解药生效 0 死；不用药 1 死（狼刀）；用毒 2 死（狼刀 + 毒药，目标重叠则 1 死）；首夜还可因猎人枪伤再追加死亡。
7. **竞选只发生一次**：`round=1` 的白天；警徽流失后不再竞选。
8. **猎人开枪是独立一步**（`hunter_shoot`），可判胜；弃枪不做判定。
9. **接任警长的 1.5 票权从下一次投票起生效**（遗言/移交所在轮次不再投票）。
10. **`setBadgePreset` 不进入事件流**：它只改隐藏状态，不推进阶段、不产生事件。
11. **退水窗口**：只在 `sheriff_speak` 内、本人发言或跳过后、每人一次；**PK 阶段不开放退水**（PK 名单在首投后确定，窗口已关）。退水者**回到警下**：保留投票权，不再有竞选发言权、不再被投。

### 5.8 边界情形

| 情形 | 处理 |
|---|---|
| 首夜无人死亡（解药生效） | 没有遗言；直接 `sheriff_signup` |
| 首夜死者被毒（非被刀） | **有遗言**（时点判定）；若是猎人则不能开枪 |
| 首夜猎人被刀 | 遗言 → 开枪 → **被枪者遗言**（同属首夜）→ 才进竞选 |
| 首夜猎人被毒 | 有遗言，**不能**开枪 |
| 首夜双死（狼刀 + 毒药，目标不同） | 两名死者都有遗言；按「狼刀 → 毒药」逐个处理（§12.1-P） |
| 同一目标同时被刀与被毒 | 只算 **1 死**；死因记 `poison`、猎人不能开枪（§12.1-P） |
| 第 2 夜起被刀 / 被毒 | 没有遗言；若是警长 → 按预设独立移交；猎人被毒不能开枪 |
| 警长被放逐 | 有遗言；遗言可调整警徽流 → `badge_transfer` →（若是猎人）开枪 |
| 猎人兼警长被放逐 | 遗言（含指定/调整）→ 移交 → 开枪 |
| 枪杀打死新接任警长 | 枪杀不产生遗言 → 该警长按自己的预设移交；无预设 → 未指定 → 流失 |
| 接任者在同一链条内死亡 | 按同一链条继续；其预设若未指定 → 流失 |
| 预设目标先于警长死亡 | 视为未指定 → 流失（§12.1-M） |
| 遗言指定无效目标 | 视为未指定 → 回落到预设；预设也无效 → 流失 |
| 全员上警且无人退水（无合格投票人） | 本局无警长（`sheriff_elected{null,'no-vote'}`），照常发言（§12.1-I） |
| 无人上警 | 本局无警长，座位升序发言（§12.1-H） |
| 仅 1 人上警 | 直接当选，跳过发言与投票（§12.1-H） |
| 上警者全部退水 | 有效候选人 0 → `sheriff_elected{null,'all-withdrawn'}` → 本局无警长，照常 `day_speak`（§12.1-K）；此时全员都是警下 |
| 退水后只剩 1 名候选 | 直接当选（`single-candidate`）→ `day_order`（与 §12.1-H 同口径） |
| 退水者是否投票 | **可以投票**：投票人 = 警下 = 存活者 − 有效候选人（含已退水者）；退水者不再进入 PK |
| 竞选（含 PK）期间有人死亡 | **不可达**：竞选期间没有任何死亡结算点（§12.1-N） |
| 放逐平票 / 全员弃票 | 平安日（§12.1-F 沿用 v1） |
| 真人出局但仍有遗言/开枪 | 出局者仍有该阶段操作权，动作完成后才转观战（警徽移交由系统执行） |

## 6. 胜负判定（屠边）

**判胜时机**（与 §5.3 的死亡链严格对齐）：

```text
死亡结算（夜死 / 放逐 / 枪杀）
  → 同一结算点的死亡全部记录完后，立即判胜一次（下表顺序）
  → 成立：victory → game_over（跳过遗言、警徽移交、开枪）
  → 未成立：继续 §5.3 后续链（遗言 → 移交 → 开枪）
遗言阶段：无死亡 → 不判胜；警徽移交不改变存活 → 不判胜
```

判定顺序：

```text
1. 若存活狼数 = 0                → 好人胜（reason: wolves-eliminated）
2. 否则若存活神数 = 0            → 狼胜  （reason: gods-eliminated）
3. 否则若存活民数 = 0            → 狼胜  （reason: villagers-eliminated）
4. 否则继续
```

- 「神」= 预言家 / 女巫 / 猎人；「民」= 村民。
- 判定使用**存活口径**（死者不计）。
- **为什么判胜必须紧跟在死亡结算之后、不能等遗言/开枪结束**：否则会出现
  「已终局还能开枪改结果」「终局后警徽还能换人」的矛盾，胜负与最终盘面不一致
  （D53 已定"每次死亡结算后即时判定"）。
- **遗言阶段本身不判胜**：遗言不产生死亡；警徽移交给存活者，不改变存活数。
- **枪杀立即判胜**：猎人开枪打死最后一名神/民 → 狼胜；打死最后一狼 → 好人胜。
- **推论（判胜优先的两个常见后果，§12.1-O 定案）**：
  ① 若猎人自己就是最后一名神/民，他的死亡已判狼胜 → **遗言与开枪都跳过**；
  ② 若首夜被枪者的死亡已定胜负 → **他的遗言同样跳过**（遗言权不改变判胜优先级）。
- 边界：**同夜双死时，神灭与民灭可以同时成立**（狼刀屠神边 + 毒药屠民边）。
  按上表顺序，理由取 `gods-eliminated`（第 2 条先命中）。
- 边界：同夜双死且**最后一狼也被毒死**时，第 1 条优先 → **好人胜**（§12.1-P ①）。

**死亡方式 × 遗言 / 警徽 / 开枪 对照表**：

| 死亡时点 / 方式 | 遗言 | 警徽移交 | 开枪 | 判胜检查点 |
|---|---|---|---|---|
| 首夜（任何死因，含被毒、被枪） | 有 | 首夜无警长，不涉及 | 若是猎人（被毒除外） | 死亡结算后立即 |
| 第 2 夜起被狼刀 | 无 | 若是警长：按预设独立移交 | 若是猎人：有 | 同上 |
| 第 2 夜起被毒 | 无 | 若是警长：按预设独立移交 | 无（被毒不能开枪） | 同上 |
| 白天被放逐 | 有 | 若是警长：遗言指定 / 预设 | 若是猎人：有 | 放逐结算后立即 |
| 白天被枪杀 | 无 | 若是警长：按预设 | 无 | 枪杀结算后立即 |
| **同一目标被刀又被毒**（同目标只算 1 死） | 按死亡时点（首夜有、第 2 夜起无） | 若是警长：按预设 | **无**（死因记 `poison`） | 结算后立即 |

> 上表按**单个死者**适用；同夜双死时两名死者分别对照本表，判胜见本节末尾。

## 7. AI 策略（新增警长 / 遗言 / 预设）

> 本节是**实现口径**（不是玩家规则）：改动只需同步 `src/ai/decider.ts` 与测试。
> 原则沿用 v1：**确定性、只用自己可见的信息、随机只走注入的 rng**。
> 本节新增的规则**不新增随机流**，全部复用同一条 `rng`。

### 7.1 夜晚与白天基础策略（沿用 v1 + 女巫/猎人）

| AI 角色 | 夜晚 | 白天发言 | 放逐投票 |
|---|---|---|---|
| 狼人 | 从存活好人中随机选刀口 | 伪装村民模板句；被查杀则反驳 | 随机投存活好人（不投队友） |
| 预言家 | 从**未验过**的存活者中随机验 | 首个白天跳预言家 + 公布最新查验 | 有存活查杀投查杀，否则随机 |
| 女巫 | 解药存在且刀口目标非自己 → 救；任意夜自救也救；毒药**仅在有存活查杀公开时**用（§12.1-D） | 模板句，不自跳（除非被查杀） | 同村民逻辑 |
| 猎人 | 无 | 模板句；可自跳猎人威慑 | 同村民逻辑 |
| 村民 | 无 | 模板句 / 站边跳出的预言家 | 有查杀投查杀，否则随机 |

**猎人 AI 开枪**：若已有公开、存活的查杀目标 → 打查杀；否则经 `rng` 抽一名存活者；
无合法目标 → **弃枪**。

### 7.2 警长竞选（新增）

| AI 角色 | 是否上警（首个白天） | 竞选发言 | 警下投票（含 PK 再投） |
|---|---|---|---|
| 狼人 | **仅「存活狼中座位号最小者」上警**；其余不上警 | **悍跳预言家**：`claim` 指向座位号最小的存活好人（非狼、≠自己），结果 `werewolf`（查杀） | 投自己的上警狼队友；无队友上警则投非狼候选人中座位号最小者 |
| 预言家 | **必上警** | 跳预言家 + 公布首夜查验（沿用 v1 模板） | 候选人不投票 |
| 女巫 | 不上警 | — | 见「好人警下投票」口径 |
| 猎人 | 不上警 | — | 同上 |
| 村民 | 不上警 | — | 同上 |

**好人警下投票（女巫/猎人/村民统一口径，只用公开 `claim`）**：

1. 候选人中**恰有 1 人** claim 预言家 → 投他；
2. 有 **≥2 人** claim → 投**座位号最小的** claim 者（确定性，不解析发言文本）；
3. 无人 claim → 投座位号最小的候选人；
4. **永不弃票**（无合法目标除外）。

**AI 退水：永不退水（确定性，不耗 rng）。** 理由：AI 的竞选发言是固定模板，退水只会缩小候选集合、
不带来任何新信息；而「AI 全托管局恒为 2 名候选人」是可测性质，保留它比让 AI 随机退水更有价值。

> **AI 全托管局的可达性**：候选人通常是「预言家 + 座位最小的狼」两名（若首夜预言家死亡，
> 则只剩 1 名候选人，按 §12.1-H 直接当选）。警下投票人 = 存活者去掉候选人：好人票向一致
> （都投同一个 claim 者）、狼票向一致（都投上警狼），两方人数不等 → **不会平票**。
> 因此 **AI 全托管局的 PK 路径不可达**；PK 由真人操作或脚本动作造出（§10-V12），不影响规则本身。

### 7.3 AI 警长的警徽预设（确定性，不得随机）

```text
aiBadgePreset(view):
  1. 我是狼            → 存活狼队友中座位号最小者；无 → null
  2. 我是预言家        → 最近一次查验为 good 且存活者；
                         无 → 公开 claim 预言家且存活的他人（多个取座位最小）；
                         无 → 座位号最小的存活他人
  3. 其他好人          → 公开 claim 预言家且存活的他人（多个取座位最小）；
                         无 → 座位号最小的存活他人
  4. 结果 = 自己或死者 → null
```

- **求值时机**：AI 警长的预设恒等于「**当前可见信息下的函数值**」。实现上可在可见信息
  变化时重算，也可在死亡时按当时信息求值——两者结果相同（信息没变则同值）。
- **不允许随机**：同一局面必得同一预设（research D3 单流口径）。
- 信息隔离：狼用队友信息、预言家用自己查验、其他好人只用公开 `claim`，均属各自可见信息。

### 7.4 AI 警长定发言顺序

`start = 自己座位`，`direction = 'asc'`（**警长先发言，其余按座位升序**）。
确定性、不耗随机；真人警长可自行选择（§12.1-J）。

### 7.5 AI 遗言说什么

| 身份 | 遗言内容（确定性模板） |
|---|---|
| 预言家 | 公布**全部**查验（按轮次排序），指认存活查杀；无查杀则声明「无查杀」 |
| 狼人 | 不承认；若有人公开 claim 查杀自己 → 反咬他；否则「我是好人，别被骗」 |
| 女巫 / 猎人 / 村民 | 好人模板句；猎人附加「我要开枪打 X」或「我不开枪」 |
| 任意身份且为警长 | 先按上表发言；**不额外指定**（省略 `badgeTo`，让生前预设按 `preset` 路径生效）；若预设为 null 则声明「警徽作废」（`badgeTo:null`） |

- AI **不跳过**遗言（`skipped:false`），保证事件流可读、可测。
- AI 在**不产生遗言的场合**死亡时不发言——但这不影响 `badge_transfer`：预设照常生效。

### 7.6 确定性与信息隔离

- 同一 `seed` + 同一动作序列 → AI 全流程决策完全一致（含上警名单、投票、预设、遗言文本）。
- 模板句是**纯函数**（不含时间/随机/外部状态）。
- 新增决策只读 `VisibleView`（§9.1 的新增字段）：狼不投队友、村民不知道金水、
  AI 看不到别人的警徽预设。

## 8. 交互定义（竖屏手机优先）

1. **竖屏优先**：布局按 9:16 设计，单列流式（顶部状态条 / 中部日志 / 底部输入面板），
   桌面宽屏自适应为左右两栏（日志 + 侧栏）。
2. **按钮驱动**，不解析自由文本指令（沿用 v1）。
3. **hot-seat 遮挡页**（D66 已定要）：真人 > 1 时，**每次行动者从真人 A 切到真人 B**
   都先显示遮挡页「**请 N 号玩家操作**」+ 确认按钮，且**同时把日志投影切换到该座位**
   （`eventsFor(seat)`）——否则上一位的夜间私有信息会残留在屏幕上。触发点：
   夜间各行动、竞选报名/发言/投票（含 PK）、定发言顺序、放逐投票、遗言、猎人开枪。
   **警徽移交是系统公告**（不产生行动者切换），因此不弹遮挡页；
   **同一真人连续操作不重复弹**（如遗言 → 开枪）。
4. 局前设置项：**种子**（可空）、**明/暗牌**、**真人数量 1–9**、开始按钮。
5. **竞选界面**：
   - 报名：两个按钮「上警 / 不上警」；显示当前上警名单与人数。
   - 上警者发言：文本框 + 跳过；显示「第 k / m 位上警者」。
   - 警下投票：只列**候选人**（+ 弃票）；显示「警上 N 人、警下 M 人」与「你的票权 1」。
   - 退水：**只在该候选人发言（或跳过）结束后出现一次「退水 / 不退水」**；点「退水」后该玩家从候选名单消失、回到警下，退水不可撤销——**发言/被投按钮消失，但警下投票阶段仍可投票**。
   - 平票：提示「N 号与 M 号进入 PK」，再发言一轮后重新投票；再平票 → 公告本局无警长。
6. **定发言顺序界面**：警长选择起讲座位与方向（升序/降序），实时预览完整顺序；
   无警长时该界面不出现，顺序固定座位升序。
7. **遗言界面**：死者操作；文本框 + 跳过；若死者是警长额外显示警徽处置，初始选项「**沿用生前预设（不修改）**」，
   可改为某个存活座位或「作废」；提示「遗言结束后才进入开枪」。
8. **警徽移交公告**：不产生遗言的场合由系统直接公布「N 号（警长）的警徽移交给 M 号」或
   「警徽作废，本局不再有警长」。
9. **警长标记与 1.5 票显示**：
   - 座位卡显示警徽图标 + 「警长 1.5 票」；全局状态条显示「警长：N 号」或「无警长」。
   - 投票面板显示「你的票权：1.5（警长）/ 1」；计票结果按 0.5 步进显示（如 3.5 : 3）。
   - **警徽流控件只对警长本人可见**：显示「当前警徽流：N 号」/「未指定」；
     预设目标已死亡时给出红字警告「目标已出局，警徽将作废」；**接任警徽时在移交公告页直接提示设置新预设**（同一屏，不额外开阶段）。
      控件只在**该警长自己的操作回合**出现（hot-seat 交接时随遮挡页一起隐藏）。
10. 观战：真人出局后输入面板消失，日志继续到终局；但**遗言 / 开枪**仍属该死者，
    这些动作完成后才转观战（**警徽移交是系统公告**；观战态仍能看公开日志）。
11. 终局：胜负阵营 + 原因 + **全员身份表** + **警徽流转记录** + 导出事件流按钮。

## 9. 事件（新增与扩展）

事件类型共 **19 类**（在 v2 草案基础上新增 6 类、扩展 3 类字段）。

既有 13 类：`game_started`、`night_started`、`roles_dealt`、`wolf_kill_decided`、`witch_action`、
`seer_check_completed`、`speech`、`vote_cast`、`vote_result`、`player_died`、`hunter_shot`、`victory`、`game_over`。
以下只列**新增与需扩展**的条目。

| # | 事件 `type` | 载荷 | 可见性 | 说明与可见性理由 |
|---|---|---|---|---|
| 1 | `sheriff_signup` | `{ seat, join, order }` | `public` | 上警名单决定「谁有投票权、谁先发言」，必须人人可见；`order` = 报名轮转序号 |
| 2 | `sheriff_withdraw` | `{ seat, round }` | `public` | 退水直接改变候选集合与投票选项，必须公开；否则无法解释「为什么这个人不在候选里」 |
| 3 | `sheriff_elected` | `{ seat: Seat \| null, reason }` | `public` | 1.5 票权从此存在，计票必须对所有人可解释；`reason` ∈ `elected`/`single-candidate`/`pk`/`no-candidate`/`all-withdrawn`/`no-vote`/`tie-exhausted`；`seat:null` = 本局无警长；计票明细在 `vote_result`（单候选直接当选的路径没有投票，故无 tally） |
| 4 | `day_speech_order` | `{ round, start, direction, order }` | `public` | 警长定序是公开决策，复盘与测试要能断言发言顺序 |
| 5 | `last_words` | `{ seat, text, skipped, cause, window }` | `public` | **遗言是公开发言**（与 `speech` 同级的信息源，AI 也要据此决策）；`window` ∈ `first-night`/`night`/`day`（`night` = 第 2 夜起）。暗牌局不因遗言翻牌——公开的是"他说了什么"，不是"他是什么身份"（发言可以撒谎） |
| 6 | `badge_passed` | `{ from, to: Seat \| null, reason }` | `public` | 接任者的 1.5 票权、旧警长的退场必须对所有玩家可见，否则计票无法解释；`reason` ∈ `last-words`/`preset`/`invalid`（`to:null` = 流失） |
| — | **警徽预设（无事件）** | `badgePreset` 只在 `viewFor(警长本人)` 中 | **隐藏（仅警长）** | 预设是隐藏信息：公开会让旁人知道警长信任谁，直接破坏推理；**预设本身不产生公开事件**，只有真正移交时产生 `badge_passed`；终局也不回溯公布 |

**扩展字段（不新增事件）**：

| 事件 | 扩展 | 说明 |
|---|---|---|
| `speech` | `stage: 'day' \| 'sheriff' \| 'sheriff-pk'` | 区分竞选发言 / PK 发言 / 白天发言；缺省 `'day'`，向后兼容 |
| `vote_cast` | `weight: 1 \| 1.5` | 该票的票权；计票口径唯一出处见 §5.5 |
| `vote_result` | `scope: 'sheriff' \| 'sheriff-pk' \| 'exile'`；`tally` 按 **0.5 步进** | 选举结果座位放 `sheriff_elected.seat`，不在 `vote_result` 里重复 |
| `player_died` | `cause: 'night-kill' \| 'poison' \| 'exile' \| 'hunter-shot'` | 暗牌局仍**不带** `revealedRole` |

- **阶段与事件同名有先例**：v1 的 `game_over` 既是阶段也是事件；本稿的 `sheriff_signup`、
  `last_words` 同理，二者分属 `Phase` 与事件 `type` 两个命名空间。
- `badge_passed` 的 `reason` 必须保留：它解释「这次移交是遗言改的、还是生前预设生效的」，
  是复盘与测试区分两种路径的唯一依据。

### 9.1 可见视图新增字段（`VisibleView` 增量）

```ts
interface VisibleView {
  // …v1 既有字段（round / phase / you / players / speeches / voteResults / pending）
  sheriff: { seat: Seat | null; badgeLost: boolean };
  candidates: Seat[];                        // 当前有效候选人（已扣退水，公开）
  withdrawn: Seat[];                         // 已退水座位（公开）
  lastWords: Array<{ round: number; seat: Seat; text: string;
                     window: 'first-night' | 'night' | 'day' }>;
  speechOrder?: { round: number; start: Seat; direction: 'asc' | 'desc'; order: Seat[] };
  myBadgePreset?: Seat | null;               // 仅当 you.seat === sheriff.seat 时存在
  pending?: { actor: Seat | 'wolf-team'; kind:
    'wolf-kill' | 'witch-action' | 'seer-check' | 'sheriff-signup' | 'withdraw'
    | 'speech' | 'speech-order' | 'vote' | 'last-words' | 'hunter-shoot' };
}
```

- **类型层隔离**：`myBadgePreset` 只在"你是警长"时出现，类型里**不存在**
  「他人预设」字段——别人的警徽流在编译期就无法被 AI 读到。
- 死者（观战）视图与生前一致，只是 `pending.actor` 不再指向他（遗言/开枪阶段除外）。

## 11. 联机预留（v3，不在本版实现）

**架构要求（现在就写进约束，避免将来返工）**：

1. **引擎必须可跑在 Node 服务端**：`engine/` 与 `ai/` 保持零 DOM/React 依赖（v1 已满足）。
2. **服务端权威**：联机时引擎只在服务端；客户端只拿 `viewFor(自己座位)` 与
   `eventsFor(自己座位)` 的投影。
3. **协议可序列化**：进聊天前的 `Action` 入参、`GameEvent` 出参必须是纯 JSON（v1 已满足）。
4. **真人座位配置化**：`createGame(seed, { humans: number[] , mode: 'open'|'dark' })`，
   不再假设「恰好 1 个真人」（这是本版必须做的改造，为联机铺路）。
5. **警长 / 遗言 / 警徽动作也走同一条 Action 通道、可序列化**：`sheriffSignup`、
   `setSpeechOrder`、`withdrawElection`、`lastWords`、`setBadgePreset`、`hunterShoot` 与既有动作同一形态，
   纯 JSON、可重放；联机时**服务端按 `actor` 校验**，客户端不得自行判定票权、警徽归属
   或隐藏预设（否则暗牌身份与警徽流会在客户端全裸）。
