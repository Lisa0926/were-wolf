## 2. 板子配置

| 角色 | 数量 | 阵营 |
|---|---|---|
| 狼人 | 2 | 狼人阵营 |
| 预言家 | 1 | 好人阵营（神） |
| 村民 | 3 | 好人阵营（民） |

**节奏推演（先口径，后结果）**——狼胜条件为「存活狼数 ≥ 存活好人数」：

- 首夜狼刀 1 好人后：2 狼 3 好（2 < 3，不触发狼胜）
- 狼最快获胜路径：夜刀 1 好（2狼3好）→ 白天放逐 1 好（2狼2好）→ **狼胜**，共 1 夜 1 日
- 好人最快获胜路径：夜刀 1 好（2狼3好）→ 日投 1 狼（1狼3好）→ 夜刀 1 好（1狼2好）→ 日投 1 狼（0狼）→ **好人胜**，共 2 夜 2 日

结论：此板子节奏偏狼速攻（狼 2 轮 vs 好人 4 轮）。S0 目的是跑通引擎，
**不做平衡调优**；S1 扩板（加女巫/猎人）时再调。

## 3. 角色技能

| 角色 | 夜间技能 | 说明 |
|---|---|---|
| 狼人 | 刀 1 名存活者 | 2 狼共同决定；**禁刀狼队友**；狼队互知身份 |
| 预言家 | 验 1 名存活者 | 结果为「好人 / 狼人」二值（不细分神民）；**禁验自己** |
| 村民 | 无 | — |

## 4. 昼夜流程与状态机

### 4.1 阶段总览

```
idle → (start+发牌) → night_wolf → night_seer → dawn → day_speak(按座次)
     → vote → exile → 胜负判定 → night_wolf（循环）… → game_over
```

首夜从天黑开始（无「第 0 个白天」变体）。

### 4.2 转移表

| 当前状态 | 动作 | 前置校验 | 下一状态 |
|---|---|---|---|
| idle | `startGame({seed})` | — | 发牌 → night_wolf |
| night_wolf | `wolfKill(target)` | target 存活且**非狼** | night_seer（预言家已死则直跳 dawn） |
| night_seer | `seerCheck(target)` | target 存活、非自己 | dawn（结算刀口死亡） |
| dawn | `confirm` | — | day_speak（首位存活者起） |
| day_speak | `speak(text)` / `skip`（当前座次） | — | 下一位存活者；全员说完 → vote |
| vote | `castVote(target)` 或 `abstain` × 存活者数 | target 为存活者（**可投自己**）；**可弃票** | 齐票后计票 → exile |
| exile | `confirm` | — | 胜负判定 → night_wolf 或 game_over |

预言家重复验同一人：规则上**不禁止**（合法但无信息），AI 策略自行避免。

### 4.3 结算与判定规则

- **夜晚结算**：刀口目标立即死亡，无救治。**死亡即翻牌**（公布身份）——
  S0 调试友好选项（真人可据此核对引擎判定），S1 可改为暗牌。
- **放逐结算**：得票最多者放逐并翻牌；**平票 = 无人放逐**（平安日）；
  弃票不计票，**全员弃票 = 平安日**（与平票同路处理）。
- **胜负判定时机**：每次死亡结算后**立即**判定（存活口径）：
  - 存活狼数 = 0 → 好人胜
  - 存活狼数 ≥ 存活好人数 → 狼胜
- **game_over**：展示胜负阵营 + 全员身份与存活表。

### 4.4 身份分配

- Fisher–Yates 洗牌 + **seeded RNG**：同一 seed → 同一局
  （发牌与 AI 决策共用同一条随机流，全程可复现）。
- 座位 1–6，真人座位随 seed 分配（不固定优待）。

### 4.5 边界情形

| 情形 | 处理 |
|---|---|
| 预言家已死 | 夜晚跳过 night_seer |
| 真人死亡 | 转观战：日志继续、无操作权，直至 game_over |
| 死者座次 | 发言/投票顺序中跳过；一切以「存活者」为口径 |
| 平票反复 | 持续平安日，游戏继续（无上限） |
| 全员弃票 | 计 0 票，平安日（与平票同路处理） |

## 5. AI 玩家策略（S0 规则驱动）

**信息隔离原则**：AI 只用其角色/阵营可见的信息决策（狼知队友；预言家记
自己的查验；村民只用公开信息）。**引擎不向 AI 泄露任何隐藏信息**——
这是可测的硬约束，也是本项目信息架构的学习点。

**扩展预留（本地知识库，D35）**：AI 决策的输入是结构化的「可见信息视图」。
将来接入 LLM 玩家 / 知识库检索（RAG）时，只需向视图追加输入源，
不改动引擎与状态机。

| AI 角色 | 夜晚 | 白天发言 | 投票 |
|---|---|---|---|
| 狼人 | 从存活**好人**中随机选刀口 | 伪装村民模板句；被查杀则喊「我不是狼，X 是悍跳」 | 随机投存活好人（不投队友） |
| 预言家 | 从**未验过**的存活者中随机验 | 首个白天立即跳预言家，公布最新查验（金水/查杀） | 若有存活查杀 → 投查杀；否则随机 |
| 村民 | 无 | 模板句（无信息 / 站边跳出的预言家） | 同预言家逻辑：有查杀投查杀，否则随机 |

**§5 补充口径（实现期确定，2026-10-18；Lisa 过目）**

上表未写死、实现时必须选定的四处，按下列口径执行。改动须同步
`src/ai/decider.ts` 与 `tests/ai.test.ts`：

1. **预言家第 2 个白天及以后**：仍沿用「公布最新查验 + claim」同一句模板
   （保证可测与可复现）。
2. **表中「随机」的范围**：存活的其他玩家，**不含自己**（自票是留给真人的
   自由度）。
3. **「有存活查杀 → 投查杀」**：查杀含**历史**查验，目标仍存活即投；多个候选
   取**最近一次**（确定性，不额外耗随机数）。村民的查杀信息来源是公开 `claim`
   字段，不解析发言文本。
4. **狼被查杀后的反驳**：只要公开 `claim` 命中自己就每轮反驳，同一确定模板，
   指控者取最近一次。

## 6. 交互定义（纯文本界面）

- **输入**：阶段驱动的座位点选（刀人/查验/投票目标）；真人发言为文本框
  （可跳过）。**不解析自由文本指令**。
- **输出**：滚动日志流——阶段标题、死讯、翻牌、发言、计票、判定。
- **节奏**：真人阶段等待操作；纯 AI 阶段自动推进（带可读延时）。

---

## 7. 实现约束（同步写进项目 AGENTS.md）

1. `engine/` 纯逻辑：**零 React/DOM 依赖**，可被 Vitest 直接驱动。
2. 所有随机经**注入的 seeded RNG**，`engine/` 与 `ai/` 内禁直调 `Math.random`。
3. AI 决策只用可见信息（信息隔离要有测试）。
4. **对局事件流是一等公民**：引擎每局产出可序列化的事件序列（发牌/夜间
   动作/发言/投票/死亡/判定），UI 只消费事件流做渲染。将来本地知识库、
   复盘工具、AI 经验积累（D35）一律以事件流为数据源——只换存储，不改引擎。
