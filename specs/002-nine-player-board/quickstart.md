### 1.1 设备准备

### 1.2 走查清单（每项都要在 375 宽下眼睛过一遍）

| # | 检查 | 预期 |

| 1 | 页面加载 | 单列布局；**无横向滚动条**（`document.documentElement.scrollWidth === 375`） |
| 2 | 状态条 | 显示「第 N 轮 · 阶段名 · 警长：N 号/无警长 · 你：N 号（身份）· 票权」 |

| 6 | 夜间女巫面板 | 「本夜刀口：N 号」+ 药况 + 三选一按钮，全部在一屏内可点 |

**判定**：横向滚动 = 0 次、被遮挡/不可点控件 = 0 个（SC-010）。

### 1.3 五种身份各玩一局（人故事 1 独立测试）

同一种子的发牌是固定的，一个种子只对应一种真人身份。因此：

> **种子与身份的对照表由实施阶段实算后回填本表**（v1 的 quickstart 就是这么做的：
> 用引擎跑 1000 个 seed，挑出「真人拿到目标身份、且 5 轮内能自然结束」的样本）。
> **本文件不预填未经验证的种子**——写死一个没跑过的 seed 等于交付假数据。

| 单人抽样 | 种子（实施阶段回填） | 真人座位 | 玩法要点 | 预期 |
|---|---|---|---|---|
| 狼人 | `待回填` | — | 夜晚选刀（队友不在选项里）；白天伪装 | 天亮公布死讯；终局见结算 |
| 预言家 | `待回填` | — | 夜晚查验（不能选自己）；白天跳身份 | 次日可见自己的查验记录 |
| 女巫 | `待回填` | — | 先看到刀口 → 决定救/毒/不用 | 救下时**当夜 0 死**；用毒时**双死** |
| 猎人 | `待回填` | — | 被刀/被放逐时可开枪 | 遗言 → 开枪 → 被枪者遗言 |
| 村民 | `待回填` | — | 无夜间行动 | 全流程到终局无卡死 |

**每局的三个断言**：
1. 自然到达 `game_over`（≤ 10 轮，SC-002）；
2. 终局原因与盘面一致（对一次座位身份表）；
3. 同一 seed 重复开局，整局记录**逐字节一致**（导出后 `diff` 两个 json 文件，SC-003）。

### 1.4 女巫用毒的 AI 口径（D13，替代旧「只在有查杀时用毒」）

| 检查 | 预期 |
|---|---|

## 2. 多真人 hot-seat（人故事 4 / 规则 V23–V24 / SC-009）

### 2.1 场景 A：2 真人、夜间行动权从 A 换到 B

设置：种子 `待回填`、明牌、真人座位 = `3`、`7`（3 号是狼、7 号是女巫/预言家的那局）。

| 步 | 操作 | 预期 |
|---|---|---|
| 1 | 开局 | 首次行动前出现**遮挡页**「请 3 号玩家操作」+ 确认 |
| 2 | 确认 | 进入 `play`；日志投影 = `eventsFor(3)`；能看到狼队友标记 |
| 3 | 3 号选刀口 → 提交 | 进入女巫环节前出现遮挡页「请 7 号玩家操作」 |
| 4 | 确认 | 日志投影 = `eventsFor(7)`；**3 号的刀口信息不再显示**（除 7 号自己该看到的刀口座位） |
| 5 | 7 号不用药 → 提交 | 不被遮挡的 AI 阶段继续推进（无遮挡页） |

**断言**：整局「真人之间切换」的次数 = 遮挡页出现次数（100%）；AI 行动 0 次遮挡页。

### 2.2 场景 B：同一真人连续操作（遗言 → 开枪）

构造：3 号真人 = 猎人，白天被放逐（或用脚本动作构造）。
**预期**：放逐结算后出现一次遮挡页（若上一次操作者不是 3 号）；遗言面板提交后
**直接**进入开枪面板，**不再弹遮挡页**（`lastHumanActor` 未变）。

### 2.3 场景 C：D77 —— 两名真人同为狼

设置：真人座位 = 两只狼（例如 `1`、`5`）。

| 步 | 预期 |
|---|---|
| 1 | 1 号（存活真人狼中座位最小者）得到 `wolf-kill` 面板 |
| 2 | 5 号**没有**刀口面板，只显示「等待狼队决定（由 1 号代表）」 |
| 3 | 1 号提交后，5 号日志里能看到 `wolf_kill_decided`（同一狼队） |
| 4 | 5 号试图提交 `wolfKill`（若 UI 有后门/测试直连引擎）→ `NOT_YOUR_TURN` |
| 5 | 1 号出局后，代表自动切到 5 号（座位最小的**存活真人**狼） |

### 2.4 场景 D：D78 —— 接任警长设警徽流走遮挡页

构造：警长（真人 A）+ 另一真人 B；让警长在**夜里被刀**（第 2 夜，无遗言）。警长生前预设了 B。

| 步 | 预期 |
|---|---|
| 1 | 天亮公布死讯（无遗言） |
| 2 | 出现警徽移交公告「N 号（警长）的警徽移交给 B 号」——**这一步不弹遮挡页** |
| 3 | 随即出现遮挡页「请 B 号玩家（新警长）设置警徽流」+ 9 宫格 + 「暂不设置」 |
| 4 | B 设置后（或点「暂不设置」）才继续后续链 |
| 5 | A 的屏幕上**从未**出现 B 的预设内容；导出记录里也搜不到 `badgePreset` |

### 2.5 场景 E：D79 —— 预设只能在自己回合改

| 步 | 预期 |
|---|---|
| 1 | 轮到他人（真人或 AI）行动时，警长的预设控件**不出现** |
| 2 | 直连引擎在他人回合提交 `setBadgePreset` → `NOT_YOUR_TURN` |
| 3 | 警长自己的夜间行动回合 / 白天回合 → 控件出现，提交成功且**不产生事件** |
| 4 | 提交后刷新页面（重开）→ 预设丢失（本版无持久化，符合 spec） |

## 5. 死亡后续三段顺序（人故事 3 / 规则 V16–V22 / SC-006、SC-007）

### 5.1 场景：警长兼猎人被放逐

构造：某人既是警长又是猎人，白天被投票放逐。

**按顺序检查日志**（事件 `seq` 严格递增）：

```text
vote_result(scope:'exile')
player_died(cause:'exile')            ← 放逐即判胜？未成立
last_words(seat=死者)                 ← ① 遗言（可改警徽流向）
badge_passed(from=死者, to=某存活者, reason:'last-words'|'preset')   ← ② 移交
hunter_shot(seat=死者, target=某人)    ← ③ 开枪
player_died(cause:'hunter-shot')      ← 枪杀新死亡（若命中）
```

**三段必须齐全且顺序固定**（规则 V18 / FR-036）：三段缺一或顺序颠倒即返工。

### 5.2 场景：第 2 夜警长被刀（无遗言）

| 检查 | 预期 |
|---|---|
| `last_words` 事件 | **0 条** |
| `badge_passed` 事件 | **1 条**，`reason:'preset'` |
| 公告 | 「N 号（警长）的警徽移交给 M 号」 |
| 新警长票权 | 下一次投票起显示「1.5 票」 |

（规则 V19 / SC-007 后半句。若没预设 → `badge_passed{to:null, reason:'invalid'}` + 「警徽作废」公告。）

### 5.3 场景：首夜双死（刀 + 毒，目标不同）

| 检查 | 预期 |
|---|---|
| 遗言条数 | 2 条，顺序 = **先被刀者、后被毒者** |
| 若被刀者是猎人 | 顺序变为 `last_words(猎人) → hunter_shot → last_words(被枪者) → last_words(被毒者)` |
| 竞选 | 全部死亡后续事项结束后才进 `sheriff_signup` |

（规则 V16/V17 / FR-021 / SC-006。）

### 5.4 场景：判胜优先（规则 V21 / FR-060）

构造：猎人自己是最后一名神（或民），其死亡已判狼胜。

**预期**：日志在 `player_died` 之后**直接** `victory` + `game_over`；
`last_words`、`badge_passed`、`hunter_shot` **一条都没有**。

## 7. 导出与重放（人故事 6 / 规则 V27 / SC-012）

1. 任一局打到终局 → 点「导出整局记录」→ 得到 `<seed>.json`。
2. 检查文件：

```jsonc
{ "schemaVersion": 2, "feature": "werewolf-v2",
  "config": { "seed": "...", "mode": "open", "humans": [3, 7] },
  "events": [ /* 19 类事件，seq 连续 */ ] }
```

3. **不接触游戏本体**，仅凭该文件回答四个问题：
   - 每轮谁先发言、顺序是什么？（`day_speech_order.order`）
   - 每轮谁投了谁、结果如何？（`vote_cast` + `vote_result`）
   - 谁在什么时候死了、死因与遗言窗口？（`player_died` + `last_words`）
   - 为什么终局？（`victory.reason` + `game_over.finalTable`）
4. 抽 10 局重复，四条全部答对 = SC-012 通过。

## 10. 常见问题

| 现象 | 处置 |
|---|---|
| 页面空白 | 看 dev server 与 browser console；确认端口 |
| 375 宽出现横向滚动 | 查新增的固定宽度 / `nowrap` / `<table>`；SC-010 不过 = 返工 |
| 同 seed 两局不一致 | 查 `engine/ai` 是否偷用 `Math.random`/`Date`；查 `decisionRequest` 是否被绕过 |
| 出现「已终局还能操作」 | 查判胜是否只在 `enterSettlement` 一处调用；`game_over` 后必须全部拒绝 |
| 双死时警徽多传了一次 | 查 `DeathRecord.wasSheriff` 是否在**记录死亡时**快照（不是比对现值） |
| 计票出现浮点误差 | 查是否有人绕过 `tallyHalf` 用了 `1.5` 累加 |

| 死者没有遗言/开枪面板 | 查 `viewFor(死者)` 是否仍给 `pending`（v2 遗言/开枪阶段必须给） |
