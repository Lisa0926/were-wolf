## User Scenarios & Testing *(mandatory)*

### User Story 1 - 完整玩一局 (Priority: P1)

真人玩家打开页面，以随机分配的身份和座位加入 6 人局（其余 5 席为 AI），
经历夜晚（狼刀/查验）、天亮死讯、白天发言、投票放逐的完整循环，
直到胜负揭晓并看到终局结算（胜负阵营 + 全员身份表）。

**Why this priority**: S0 的出口条件就是"端到端跑通一局"。没有这个，
其他一切都无从验证。这是最小可独立交付的价值单元。

**Independent Test**: 真人分别以狼人/预言家/村民身份各完整玩一局，
每局都自然到达终局结算画面，游戏过程无卡死、无规则漏洞。

**Acceptance Scenarios**:

1. **Given** 玩家开始新对局, **When** 身份发放完成, **Then** 玩家看到自己的
   身份与座位号，其余 5 人身份不可见
2. **Given** 玩家是狼人且处于夜晚, **When** 选定刀口（不能选狼队友）,
   **Then** 进入预言家/天亮阶段，天亮公布死者并翻牌
3. **Given** 玩家是预言家且处于夜晚, **When** 选定查验目标（不能选自己）,
   **Then** 玩家得知该目标"好人/狼人"二值结果
4. **Given** 白天发言轮到玩家, **When** 玩家输入发言或选择跳过,
   **Then** 流转到下一位，直至进入投票
5. **Given** 投票轮到玩家, **When** 玩家投票给任意存活者（含自己）或弃票,
   **Then** 齐票后公布计票与放逐结果（平票/全弃 = 无人放逐）
6. **Given** 任一死亡结算完成, **When** 触发胜负条件, **Then** 立即进入终局
   结算（狼全灭 = 好人胜；狼数 ≥ 好人数 = 狼胜）

---

### User Story 2 - 规则判定可信 (Priority: P2)

玩家（作为验收者）能够核对引擎每一步判定：死亡即翻牌让人能验证刀口与
放逐是否执行正确；固定种子可复现让同一局可以重演检查。

**Why this priority**: "能玩"不够，必须"判得对"。游戏类验收基线要求
规则判定正确，这是该项目作为学习载体的核心验证点。

**Independent Test**: 用固定种子跑同一局两次，过程与结果完全一致；
按验收清单（`projects/werewolf/docs/游戏规则.md` §8）逐项核对全部通过。

**Acceptance Scenarios**:

1. **Given** 同一随机种子, **When** 完整进行两局, **Then** 发牌、AI 决策、
   全部过程与终局完全一致
2. **Given** 预言家已死亡, **When** 进入下一个夜晚, **Then** 跳过查验环节
   直接到天亮
3. **Given** 玩家已死亡, **When** 对局继续, **Then** 玩家以观战身份看到
   完整过程直至终局（无操作权）
4. **Given** 多轮平票, **When** 连续多个白天无人被放逐, **Then** 游戏正常
   继续循环，不卡死不崩溃

---

### User Story 3 - 整局事件流可导出 (Priority: P3)

一局结束后，整局过程（发牌、夜间动作、发言、投票、死亡、判定）以
结构化、可序列化的事件序列形式存在，能被导出查看。

**Why this priority**: 为 Lisa 将来的本地知识库（定位：对局复盘，D35）
预留数据源。S0 只保证数据出口存在，不做存储与复盘界面。

**Independent Test**: 任选一局，导出事件流后仅凭事件流就能完整重建
整局的可见叙事（谁说了什么、投了谁、谁死、何时终局）。

**Acceptance Scenarios**:

1. **Given** 一局结束, **When** 获取该局事件流, **Then** 得到完整、
   可被机器解析的有序事件序列，覆盖从发牌到终局的全部关键节点
2. **Given** 事件流, **When** 第三方按序读取, **Then** 无需访问游戏本体
   即可重建整局时间线

---

### Edge Cases

- 预言家第一夜就被刀死 → 之后的夜晚直接跳过查验环节
- 真人玩家在夜晚被刀 / 白天被放逐 → 转观战，AI 打完整局
- 投票全员弃票 → 与平票同路处理：无人放逐，平安日
- 狼人最快获胜路径（1 夜 1 日）→ 终局判定在放逐结算后立即触发
- 平票反复出现 → 无上限循环平安日，游戏不崩溃、不卡死
- AI 决策不得使用其角色不可见的信息（信息隔离，防"透视"作弊）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 按 6 人局配置发牌：狼人 ×2、预言家 ×1、村民 ×3，
  身份与座位随机分配
- **FR-002**: 夜晚 MUST 依次执行：狼人选刀（禁止选狼队友）→ 预言家查验
  （禁止验自己，结果为"好人/狼人"二值）
- **FR-003**: 死亡 MUST 即时翻牌（公布身份），并在每次死亡结算后立即
  判定胜负（存活狼 = 0 → 好人胜；存活狼 ≥ 存活好人 → 狼胜）
- **FR-004**: 白天 MUST 按座次让所有存活者依次发言（真人可输入或跳过），
  然后进入全员投票
- **FR-005**: 投票 MUST 允许投任意存活者（含自己）或弃票；得票最多者
  放逐；平票或全员弃票 = 无人放逐
- **FR-006**: 预言家死亡后，夜晚 MUST 跳过查验环节
- **FR-007**: 真人死亡后 MUST 转为观战模式（可见全部公开信息、无操作权）
  直至终局
- **FR-008**: AI 玩家 MUST 仅依据其角色可见信息决策（狼知队友、预言家
  知自己查验、村民只知公开信息），不得获取任何隐藏信息
- **FR-009**: 系统 MUST 记录完整对局事件流（发牌/夜间动作/发言/投票/
  死亡/判定），可序列化导出
- **FR-010**: 同一随机种子 MUST 完整复现同一局（发牌与 AI 决策共用
  同一随机流）

### Key Entities *(include if feature involves data)*

- **对局（Game）**: 一次完整游戏实例；含随机种子、当前阶段、存活名单、
  胜负结果
- **玩家（Player）**: 6 个席位之一；属性：座位号、是否真人、身份、
  存活状态
- **角色（Role）**: 狼人/预言家/村民；决定夜间行动与所属阵营
- **阶段（Phase）**: 夜晚狼刀 → 夜晚查验 → 天亮 → 发言 → 投票 → 放逐 →
  （判定）循环；终局为特殊阶段
- **事件（Event）**: 对局中已发生的一等公民事实（谁做了什么、结果如何），
  有序组成事件流

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 真人以全部 6 种「身份 × 座位」抽样组合各完成至少一局，
  100% 到达终局结算，无卡死或规则漏洞
- **SC-002**: 验收清单（`projects/werewolf/docs/游戏规则.md` §8）全部 9 项检查通过，
  其中身份分配/昼夜流转/投票三处状态机判定正确率 100%
- **SC-003**: 同一种子重复运行 100 次，整局过程与结果完全一致（100%）
- **SC-004**: 任意一局的事件流导出后，第三方仅凭事件流可 100% 重建
  整局可见叙事（无信息缺失）

## Assumptions

- 单机运行：无后端、无账号、无持久化；刷新页面即重开新局
- S0 界面为纯文本形态：日志流展示 + 阶段驱动的点选/文本输入，
  不解析自由文本指令
- AI 玩家为规则驱动（启发式 + 模板发言），不调用大语言模型
- 规则细节（含死亡翻牌、可弃票可自票等已拍板项）以
  `projects/werewolf/docs/游戏规则.md` 为唯一事实来源，Lisa 已于 2026-10-18 审定
- 技术选型与实现级约束已由 Lisa 拍板，作为独立决策记录于
  `projects/werewolf/AGENTS.md`；本 spec 只描述 WHAT，不重复实现细节
- S0 范围外：真人联机、小程序、扩展角色（女巫/猎人/警长）、遗言、
  LLM 玩家、知识库本体
