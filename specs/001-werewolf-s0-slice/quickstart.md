# 快速开始：端到端验证指南（实现完成后执行）

**特性**: 001-werewolf-s0-slice | 前置：`projects/werewolf/` 已按 plan 落地

> 本文件是 **验证/运行指南**，不含实现细节（实现在 tasks 阶段）。
> 每个场景给出：步骤 → 预期。全部通过 = 规则 §8 验收清单 9 项全勾。

## 0. 前置与启动（§8 第 1 条）

```bash
cd projects/werewolf
pnpm install
pnpm dev        # 打开终端给出的 http://localhost:5173
```

**预期**：页面打开，出现种子输入 + 开始按钮（无 console 报错）。

## 1. 完整玩一局（§8 第 2 条；SC-001 抽样）

**三身份抽样必须用三个种子**：同一种子的发牌是固定的（FR-010 硬约束），
一个种子只对应一种真人身份，无法用 `demo-1` 一个种子覆盖三种身份。
下表种子由引擎实算核对（2026-10-18）：

| 身份抽样 | 种子 | 真人座位 | 玩法要点 | 预期 |
|---|---|---|---|---|
| 狼人 | `demo-7` | 5 号 | 夜晚选刀（面板不出现狼队友为选项） | 天亮公布死讯并翻牌；终局见结算表 |
| 预言家 | `demo-8` | 2 号 | 夜晚查验（不能选自己），结果二值 | 次日可见自己的查验结果 |
| 村民 | `demo-1` | 6 号 | 夜晚无操作，白天发言/跳过 | 全流程到 game_over 无卡死 |

**预期**：三局均自然到达终局结算（胜负阵营 + 全员身份表）；
**同一 seed 重复开局**，发牌、AI 行为、结果**逐字一致**（§8 第 3 条）。

> 附：观战体验可用 `demo-3`（真人当预言家，首夜即被狼刀，直接进入观战态）。

## 2. 观战与边界（spec US2 场景）

- 被刀/被放逐后：输入面板消失、日志继续滚动直至终局。
- 平票日：日志显示"平票，无人放逐"，游戏继续（可多刷几局构造）。
- 预言家先死：后续夜晚日志直接从"天黑"跳到"天亮"（无查验环节）。

## 4. 事件流导出（SC-004 人工复核）

1. 任一局打到 game_over → 点"导出事件流"，得到 `.json` 文件；
2. 打开文件检查：含 `schemaVersion/seed/events`，事件按 `seq` 递增，
   覆盖发牌→夜间动作→发言→投票→死亡→判定；
3. 仅凭该文件（不接触游戏本体）能口述整局时间线。

## 5. 常见问题

| 现象 | 处置 |
|---|---|
| 页面空白 | 看 dev server 与 browser console；确认 5173 端口 |
| 同种子两局不一致 | 违反 FR-010，返工（先查 engine/ai 是否偷用 Math.random） |
| AI 阶段卡住不推进 | 查 ui 驱动循环的 pendingDecision 分支 |
